# Learnings Inbox - code-review

Supporting history, not workflow authority. Read it only for a relevant recurring review gap and
reverify the lesson against the current skill and target rules. Append or consolidate entries
only when explicitly authorized in this repository; never modify this inbox from an unrelated
task or another project's working tree. Project-wide reporting follows the target's
[self-improve loop](../../../docs/standards/self-improve-loop.md).

## Entry Format

```markdown
## <YYYY-MM-DD> <short-slug>

- Symptom: <what went wrong or was missing during a review run>
- Root cause: <routing gap, checklist gap, unclear rule, tooling issue, or unknown>
- Verified fix: <what worked and how it was verified; mark "hypothesis" when not verified>
- Proposed durable update: <SKILL.md | references/<file>>
```

Rules: no secrets, personal data, identity objects, diff content or finding text from real
reviews. Keep entries short; the durable patch carries the detail.
