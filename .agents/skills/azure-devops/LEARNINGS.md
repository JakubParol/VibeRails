# Learnings Inbox - azure-devops

This is supporting history, not workflow authority. Read it only for a relevant recurring
issue and reverify the lesson against the current MCP. Append or consolidate entries only when
explicitly authorized in the owning repository; do not modify this inbox from an unrelated task.
Current capture rules are in
[the failure-learning pattern](references/context-and-learning.md#failure-learning-update-pattern).

## Entry Format

```markdown
## <YYYY-MM-DD> <short-slug>

- Symptom: <failing action or command class and sanitized error>
- Root cause: <MCP capability, permission, schema, provider-state issue, or unknown>
- Verified fix: <MCP operation or guidance change, plus how it was verified; mark "hypothesis"
  when not verified>
- Proposed durable update: <SKILL.md | references/<file> | adopting repo docs>
```

Rules: no secrets, tokens, personal data, identity objects, or customer content. Keep entries
short; the durable patch carries the detail.
